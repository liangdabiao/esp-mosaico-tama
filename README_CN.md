# tamaweb_pet 电子宠物 · 完整说明（大白话版）

一句话：把浏览器游戏 **Tamaweb** 的养成内核搬到 ESP32 触摸屏上，**纯离线、纯点按**，
一只宠物从蛋养到死大约 **4.2 小时**。

- 英文技术文档：[README.md](README.md)
- 所有数值都写在 `main/twp_data_tables.h` 里，每个常量都标了原作 JS 的出处
- 数值单位是 **0.01**：`10000` 就是 `100`，`3500` 就是 `35`

---

## 1. 一分钟看懂怎么玩

1. 标题页点一个名字（豆豆/团团/米粒/阿旺/花卷/布丁/汤圆/奶昔），再点 **开始**。
2. 先是一颗 **蛋**，4 分钟真实时间后孵化。蛋期间任何照顾操作都会被拒绝（"蛋还没孵化"）。
3. 孵化后你要一直盯着 5 个条：**饥饿、心情、精力、清洁、健康**。哪个空了都会出事。
4. 底部 8 个按钮就是全部照顾动作：**喂食 玩耍 商店 洗澡 铲屎 喂药 睡觉 唤醒**。
5. 宠物会主动 **提要求**（右上角气泡："想洗澡 / 想吃披萨 / 想玩…"）。点气泡=接受，
   在时间内做到就加心情，超时既扣心情又记一笔差照顾。
6. 照顾的钱靠 **小游戏 + 每日任务** 赚，钱花在 **商店买食物**。
7. 从小养得好，成年变成 **善良型**；养得差变成 **叛逆型**。这就是本作的"结局分支"。
8. 三条线同时崩（比如又饿又脏又病）会 **死**；一条命只有 **一次复活**。

## 2. 核心状态：4 条需求 + 1 条健康

每条需求 0~100，每分钟按下面的速度往下掉（"成年"速度，其它阶段乘倍率）。

| 状态 | 每分钟掉 | 成年不干预多久归零 | 归零/偏低会怎样 |
|---|---|---|---|
| 饥饿 | 0.20 | 500 分钟 ≈ **33 分钟真实** | 算"照顾差"，健康被拖下来 |
| 心情 | 0.32 | 312 分钟 ≈ **21 分钟真实** | 算"照顾差" |
| 清洁 | 0.16 | 625 分钟 ≈ **42 分钟真实** | 算"照顾差" |
| 精力 | 0.05 | 2000 分钟 ≈ **2.2 小时真实** | 归零自动睡着；太累玩不了小游戏 |
| 健康 | 不直接掉 | — | 见下 |

**健康怎么变**：它向"四条需求的平均值"靠拢。
比平均值高 → 每分钟 −0.1；比平均值低 → 每分钟 +0.2；**生病时不看平均值，每分钟硬掉 0.5**。

**阶段倍率**（所有需求一起乘）：宝宝 ×1.65、少年 ×1.46、成年 ×1.0、老年 ×0.8。
所以宝宝期最容易养死：饥饿 20 分钟真实时间就空。

## 3. 便便、生病、死亡、复活

- **膀胱**：每分钟 +0.21，攒满 100 就拉一坨（约 32 分钟真实一坨），地上最多 **3 坨**。
- **每坨便便让清洁衰减 +50%**（3 坨就是清洁快 1.5 倍）。铲屎 +5 清洁。
- **照顾差**的判定（任一成立即算）：四条需求里有 **0**、健康 ≤ 10、便便满 3 坨。
- 照顾差会累计" neglect 分钟"，一旦转为好好照顾就 **清零**：

| 阶段 | 生病阈值（一半） | 死亡阈值 | 换算真实时间 |
|---|---|---|---|
| 宝宝 | 150 | 300 | 病 10 分钟 / 死 20 分钟 |
| 少年 | 200 | 400 | 病 13 分钟 / 死 27 分钟 |
| 成年/老年 | 250 | 500 | 病 17 分钟 / 死 33 分钟 |

- **生病**时宠物头上出骷髅图标，健康开始快掉。此时 **喂药**：健康 +40、心情 −20、
  neglect 直接回到阈值的 1/4（救命不救因，还得去喂饭洗澡）。没病喂药会被拒绝。
- **死因**三种：照顾太差、健康归零、老死（到年龄自然走）。
- **复活**（每命一次）：四条需求拉到 60、健康拉到 80、便便清零、剩余寿命至少留 600 分钟。
  用过的话死亡页只剩"重来"。

## 4. 成长阶段与两种成年形态

| 阶段 | 进入年龄（游戏分钟） | 真实时间（从蛋开始算） |
|---|---|---|
| 蛋 | 0 | 0 |
| 宝宝 | 60 | **4 分钟** |
| 少年 | 480 | **32 分钟** |
| 成年（定形态） | 1380 | **约 1.5 小时** |
| 老年 | 2580 | **约 2.9 小时** |
| 自然死亡 | 3780 | **约 4.2 小时** |

**形态判定**在"少年→成年"那一刻结算：从孵化起每一分钟都采样，
"好分钟"= 四条需求都 ≥ 30 **且** 健康 ≥ 50。好分钟占比 ≥ **60%** → **善良成年**，
否则 → **叛逆成年**（外观不同）。满足心愿会额外记 2 分钟好照顾，忽略心愿则记 2 分钟差照顾，
所以气泡不是装饰，它直接改结局。

## 5. 时间尺度（本作最重要的一个取舍）

- **4 秒真实时间 = 1 游戏分钟**（30 FPS 下每 120 帧走一格，常量 `FRAMES_PER_TICK` 在 `main/game.c`）。
- 板子 **没有带电池的 RTC**，所以：关机/断电期间时间 **停住**，开机从存档那一分钟继续。
  原作靠真实墙上时钟，这里 **故意不做离线追赶**（追了就是凭空判死）。
- 标题页和游戏进行页 **不走表**（此时谈不上 neglect）；**商店页和游戏中心页照常走表**，
  所以不能靠开菜单冻结需求。
- 想改节奏只改 `FRAMES_PER_TICK` 一个数：调成 30 就是 1 秒 1 分钟（整条生命约 63 分钟），
  回归脚本 `tools/validate_ui.py` 里的 `FPT` 同步改即可。

## 6. 金币循环：小游戏/任务赚钱 → 商店买饭

- 开局：**15 金币**，自带库存 面包×5、披萨×2、药水×1。金币上限 9999，单种库存上限 99。
- **小游戏奖励**：每次命中 +10 金，通关再 +20，**单局封顶 80 金**。
- **每日任务**：3 条，目标各 1~3 次，完成 **立刻到账 25 金**；每 480 游戏分钟
  （**约 32 分钟真实**）换一批。任务种类：喂食 / 玩耍 / 获胜 / 洗澡 / 铲屎 / 购物。
- **心愿气泡**：每 120~280 游戏分钟（**8~19 分钟真实**）来一条，
  必须 **在 80~160 游戏分钟（5~11 分钟真实）内**完成对应动作或点气泡。
  达成：心情 +40、记 2 分钟好照顾；超时：心情 −10、记 2 分钟差照顾。
  心愿种类：想吃某样东西 / 想玩 / 想洗澡 / 要铲屎 / 想睡觉（不满足条件时不会刷出来，
  比如没便便就不会要铲屎）。

### 食物与药品表（商店 7 行）

| 商品 | 价格 | 饥饿 | 心情 | 健康 | 备注 |
|---|---|---|---|---|---|
| 面包 | 2 | +15 | 0 | +2 | 唯一健康为正的日常食物 |
| 披萨 | 10 | +40 | +5 | −5 | **最爱**：实际 +60，永远不会吃腻 |
| 汉堡 | 15 | +40 | +10 | −15 | |
| 意面 | 10 | +25 | 0 | 0 | |
| 寿司 | 30 | +40 | +10 | +20 | 贵但健康 |
| 巨无霸 | 40 | +100 | +50 | −40 | 一口回满，代价是健康 |
| 药水 | 20 | — | −20 | +40 | 只在生病时有用，平时不给吃 |

### 喂食的拒绝规则（都有对应提示）

- 饥饿已经 ≥ 85 → "已经吃饱了"（最爱例外，最爱永远吃得下）。
- 同一种食物连喂 3 次 → "吃腻这个了"（最爱例外）。
- 库存 0 → "没有库存了"；睡觉中 → "它在睡觉"；蛋 → "蛋还没孵化"；死了 → 直接不响应。
- 只有 **真正吃下去** 才扣库存，被拒绝不吃东西。

## 7. 四个小游戏（操作方式各不相同）

| 小游戏 | 怎么玩 | 轮数 | 判定窗口 | 满分 |
|---|---|---|---|---|
| 方向反应 | 宠物中间弹出大箭头，2 秒内点同方向的箭头 | 5 | 每轮 2 秒 | 5 |
| 时机钓竿 | 钩子在轨道上来回扫，点在绿色亮区内停钩 | 5 | 每轮 5 秒（3 个来回） | 5 |
| 作物记忆 | 先按顺序亮 3/4/5 个蔬菜，再照同样顺序点一遍 | 3 | 每个 0.6 秒展示 + 答题预算 | 12 |
| 梳理点点 | 6 个位置里哪个在动就点哪个，点中变星 | 8 | 每个 1.5 秒 | 8 |

- 亮区每轮变窄（时机钓竿），序列每轮变长（作物记忆），会动的位置会跳（梳理点点）。
- 进游戏前会查精力：**精力 < 15 拒绝**（"太累了，玩不动"），商店/游戏中心里卡片变灰。
- 结算：通关 **心情 +25**、失败 **心情 +10**，都 **消耗精力 10、饥饿 5**；
  金币 = 命中×10 +（通关 20），封顶 80。
- 小游戏期间 **养成计时暂停**，但结束后一切照旧。

## 8. 页面与按钮（480×480，含坐标，方便真机验证）

```
标题页 ──点名字+开始──► 主页 HOME ──┬── 喂食页（6 格库存 + 返回）
                                    ├── 商店页（7 行购买 + 返回）
                                    └── 游戏中心 ──点卡片──► 小游戏页（返回=结算回中心）
主页 ──死亡──► 死亡页（复活 / 重来）
```

主页从上到下：

| 区域 | 位置 | 内容 |
|---|---|---|
| 标题行 | 顶部 | 名字（左）、阶段（右，如"宝宝/少年/善良成年/老年"） |
| 数值 | y≈40 | `年龄分钟 + 体重克`（左）、金币（右） |
| 5 条状态 | 左列 x16：饥饿/精力/健康；右列 x236：心情/清洁 | 每条 160 宽 |
| 宠物 | 中心 (240, 226)，4 倍缩放 | 会上下轻微浮动；吃饭有动画，进化有星星 |
| 状态图标 | (150, 172/204) | 睡觉 ZZZ、生病骷髅 |
| 便便 | 固定 3 个位置 | 最多 3 坨 |
| 心愿气泡 | (310, 158) 158×58 | 剩余时间 < 30 分钟时边框闪红 |
| 任务板 | (10, 300) 460×60 | 3 行"任务名 进度/目标"，完成打勾，右侧显示第几天 |
| 8 个按钮 | y=366，每个 54×88，x=6+58i | 喂食 玩耍 商店 洗澡 铲屎 喂药 睡觉 唤醒 |
| 提示气泡 | 宠物上方 | 拒绝原因/动作反馈，90 帧（3 秒）后消失 |

按钮功能：喂食=开喂食页；玩耍=开游戏中心；商店=开商店页；洗澡=清洁 +35、精力 −3；
铲屎=清一坨 + 清洁 +5；喂药=治病；睡觉=精力 ≤ 70 才能主动睡（否则"还不困"）；
唤醒=叫醒，心情 −5（"被吵醒了，不开心"）。睡着时精力每分钟 +1.45，到 90 自动醒
（从 0 睡到自然醒约 4 分钟真实时间）。

## 10. 存档、音效

- **存档**：NVS，namespace `tamaweb`，key `pet`，固定 **96 字节**，魔数 `TWP2` + 末尾 2 字节校验和。
  正常每 30 帧（约 1 秒）最多写一次；**死亡和进化立刻写**。
  魔数/版本/校验和任一不对 → 当作没有存档，从新蛋开始（v1 旧档就是靠这个规则被安全丢弃）。
- **音效**（RTTTL 合成，7 种）：点击、照顾成功、拒绝/答错、通关、失败、进化、死亡。

## 11. 代码结构：谁负责什么

| 文件 | 职责 | 依赖 |
|---|---|---|
| `main/twp_model.c/.h` | 养成内核：衰减、喂食拒绝、便便、睡眠、生病、形态、死亡复活、存档序列化 | **零依赖**（纯 C，可在电脑上跑测试） |
| `main/twp_games.c/.h` | 四个小游戏引擎，共用一个状态机（PLAY/SHOW/REST/DONE） | 纯 C |
| `main/twp_data_tables.c/.h` | 所有可调数值 + 原作 JS 出处 | 纯 C |
| `main/game.c` | 视图与页面流程：布局、点击分区、渲染、提示 | 引擎头 |
| `main/game_module.c` | 引擎适配层 + `state_json`（回归脚本读它） | Raylib Lite |
| `main/twp_store.c` | NVS 读写 | ESP-IDF |
| `main/twp_sfx.c`、`rtttl_player.c` | 音效 | ESP-IDF/BSP |
| `main/twp_cjk_*` | 中文点阵字模 | — |
| `tests/` | 宿主单元测试（两个套件） | MinGW gcc |
| `tools/` | 回归、截图、字模生成、回放脚本 | Python |

**三条铁律（改代码前先看）**：

1. **输入判定只在 update 阶段**。点击分区每帧在 `build_zones()` 里重建，`render()` 只读状态、
   绝不参与计算——否则无头回放（只渲染最后一帧）会拿到 0 值，出现"看得到按钮点不动"。
2. **tick 换算集中在一个常量** `FRAMES_PER_TICK`，模型只认"分钟"，不认帧。
3. **随机数按名字/游戏 id 播种**，所以同一局的重放结果确定，回归脚本能断言分数。

## 12. 素材与中文怎么来的

- 素材：`assets_src/generate_sprites.py` 画一张 4×10、共 **39 帧**的精灵表
  → `pack_game_assets.py` 打包成 `assets/generated/tamaweb.atlas`
  （**123,524 / 262,144 字节**）→ 直接编进固件，不占数据分区。
- 中文：`tools/gen_cjk_font.py` 从 `UI_STRINGS` 以及 `main/game.c`、`main/twp_data_tables.c`
  里的中文字面量提取字形，生成 `main/twp_cjk_glyph_data.h`（**188 个字模**）。
  **所以新增中文标签必须写在这两个文件里**，写到别的文件会静默丢字；
  `python tools/gen_cjk_font.py --check` 就是这条规则的看门狗。

## 15. 真机状态：已装上，还差两件事要你亲手确认

装机证据（`iris device-status` / `iris logs --snapshot`）：设备 ID 未变
`4553502d…8602`，`firmware_mode=normal`，新 Boot ID，`crash_count 0`，
日志有 `first frame presented; OTA image accepted`，之后 5 分钟一直
`logic=30.0 display=30.0 dropped=0 errors=0`，内存平稳。

raylib-lite 游戏 **不提供屏幕镜像**，所以 `iris screenshot` 拿不到画面，以下两点只能靠眼睛和手：

1. **面板观感**：缩放、颜色、中文字是否清晰。
2. **触摸**：驱动每约 130 毫秒刷一条 `cst9220: Malformed report header: first=0xab marker=0xab`。
   原因是驱动把 `0xAB` 当作应答写进报告寄存器 `0xD000`，回头又规定"首字节是 0xAB 就是坏帧"，
   所以 **手指没按的时候读到自己写的应答** 就会刷这条警告——它可能只是空转噪音。
   真手指按下时控制器会不会发布合法报告，只有实际按一下才知道。

（顺带一句：日志快照里还能看到 `muse_companion`、`octop_wifi`、`set brightness to 0%` 这些行，
它们 **不属于本应用**——在编译产物 ELF 里搜不到这些标签，是 retained log 混进了别的镜像的日志。）

## 16. 已知取舍（这些不是 bug）

- **不联网**：原作的云存档、社交、活动全都不做，纯离线单机养成。
- **不做离线追赶**：板子没有电池时钟，合盖/断电期间时间停住（第 5 节）。
- **素材从简**：39 帧程序生成的像素图，不追求还原原作美术。
- **没有键盘**：名字从 8 个预设里选，不输入自定义名字。
- **原作 27 种任务只实现 6 种**、活动只实现 4 个，都是玩法内核里能自洽的部分。
- **无屏幕镜像**：引擎限制，验收靠日志 + 人眼。
